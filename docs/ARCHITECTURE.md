# 架构与实现边界

## 服务与模块

单个 Rust 可执行程序使用 `rmcp` 和 Tokio 提供 MCP stdio 服务，只暴露五个文件
工具。每个进程绑定一个工作根目录；不启动 HTTP 服务，不执行 Shell 命令。

| 模块 | 职责 |
| --- | --- |
| `main.rs` | CLI、工作根目录、全局线程预算和 stdio 生命周期 |
| `server.rs` / `types.rs` | 工具定义、JSON Schema、只读/写入标注、调度及结果限额 |
| `encoding.rs` | 严格编码校验、流式解码、文本与源字节边界对应 |
| `files.rs` / `workspace.rs` | 读写编辑、版本检查、原子提交、路径约束 |
| `search.rs` / `control.rs` | 并行遍历、匹配、截止时间及取消传播 |

目录遍历、忽略规则和 glob 复用 `ignore` / `globset`，匹配与上下文复用
`grep-regex` / `grep-searcher`，编码映射复用 `encoding_rs`，差异预览使用
`similar`，摘要使用 `blake3`。阻塞文件操作通过 `spawn_blocking` 执行。

## 严格编码层

自动模式以固定缓冲完整验证 UTF-8 和 GBK，并同时计算原始字节摘要。
UTF-8 BOM 优先；纯 ASCII 标记为 `ascii`；两种编码均合法的非 ASCII 文件
标记 `ambiguous`，读取和搜索默认解释为 GBK，修改必须指定编码。

GBK 在库映射以外增加单/双字节结构校验，拒绝 GB18030 四字节序列。非法字节、
不可表示字符和 NUL 不会被静默替换。解码只在内存发生，不创建 UTF-8 文件副本。
UTF-16/32、单文件混合编码和二进制不在首版支持范围内。

显式编码搜索可以一边严格解码一边匹配；自动检测需要先验证再搜索，因而增加
一次读取。底层搜索器不直接启用宽松编码转换，避免非法字节被替换后误匹配。

## 保留原字节的编辑

`edit_file` 先解码用于文本定位，所有 `old_string` 都基于同一个原始版本。
默认要求唯一匹配，`replace_all` 允许多个非重叠匹配；跨修改的重叠会被拒绝。

确定替换区间后，把 UTF-8 文本边界映射回原 GBK/UTF-8 字节边界，只编码
`new_string`，其余区间直接复制原始字节。这样保留未修改区域的非规范映射、
BOM、CRLF/LF 和末尾换行，避免整篇解码再编码改变原文件。

`write_file` 是完整覆盖，按输入内容重新编码，并保留已有文件的编码和 UTF-8
BOM；输入换行不会规范化。新文件默认 UTF-8，可显式选择 GBK。`dry_run` 返回
差异及预期结果摘要，不创建或提交文件；实际提交仍使用读取时的 revision。

## 版本与安全提交

已有文件的覆盖和编辑必须提供 BLAKE3 `expected_revision`。服务内写操作串行，
提交前再次验证原文件摘要，然后将目标编码字节写入同目录临时文件并刷新，
最后原子替换目标。新建使用禁止覆盖提交，失败时保留原文件。

Windows 在关闭临时文件写句柄后使用 `ReplaceFileW` 保留文件安全属性，避免
替换源的独占打开与自身句柄冲突；Unix 保留权限位并刷新目录。
原子替换改变文件身份，Unix 不保证保留 owner/group、扩展属性或 ACL。
只读文件、多硬链接及项目内符号链接/junction 不允许修改。

根目录约束和版本核对适用于受信任的本地项目。与不配合锁的外部程序之间
仍有“最终检查 → 替换”的竞争窗口，也不防御恶意进程并发重命名目录。
网络盘、云占位文件和特殊文件不属于首版性能验收范围。

## 有界检索与取消

搜索不预先收集全部路径，不维护持久化索引、后台查询会话或续查游标。默认
遵守忽略规则并跳过隐藏文件；版本控制元数据和本服务临时文件始终跳过。

| 资源 | 首版限制 |
| --- | --- |
| 活动搜索 | 最多两个，共享最多 `min(逻辑 CPU 数, 8)` 个搜索工作线程 |
| 单请求线程 | 默认分配全局预算的一半，最少一个；等待也计入超时 |
| 搜索时间 | 默认 10 秒，可设 1–300000 毫秒 |
| 返回数量 | 默认 100，最多 10000；上下文也计入数量 |
| 工具输出 | 最多 64 KiB；长匹配行返回命中附近片段并标记截断 |
| 文件修改 | 输入和结果最多 32 MiB |
| 流式读取 | 默认不使用 mmap；读取单行最多 1 MiB，检索缓冲约 1 MiB |

MCP 请求取消和截止时间传到遍历及读取循环。达到时间、数量、输出限额或遇到
文件错误时返回已有结果和未完成原因；`complete=false` 时零匹配不能证明没有
匹配，应缩小目录或过滤条件后再查。`count` 统计匹配行数，不是匹配出现次数。

逐行正则支持 LF/CRLF；不支持 PCRE2 回溯引用和 look-around。搜索结果顺序受
并行扫描影响，不应依赖固定顺序。详细工具参数以 MCP `tools/list` 为准。

## 验证与扩展范围

Rust 集成测试检查字节保留、冲突、编码、路径与资源限制；Python stdio 冒烟
覆盖真实协议调用。性能和客户端的实测范围见 [VALIDATION.md](VALIDATION.md)。
持久化索引、跨文件事务、远程服务与客户端强制拦截暂不提供。
